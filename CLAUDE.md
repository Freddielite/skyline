# Skyline: project notes

Isometric city builder for Android. React + Vite + canvas, packaged with Capacitor.
Project folder on Freddie's machine: `/home/freddielite/Downloads/skyline`
App ID: `com.wyntek.skyline` · Current version: **0.9.0**

This file is the handover: what has been built, how to push it to the phone, and the rules for future changes.
Anyone (person or AI assistant) working on this project should read it first.

---

## Rules for every change

1. **Always end with the push command.** Every fix or feature, however small, ends with the full push command below, written out exactly, so it can be copied and run without looking anything up.
2. **Always bump the version** in `package.json` (0.6.1 → 0.6.2 and so on). The game shows "Updated to version X" on first launch and the version in Menu, which is how we confirm the phone really got the new build.
3. **Deliver the whole project as `skyline.zip`**, with the files at the top level of the zip (no `skyline/` folder inside), and without `node_modules/`, `dist/` or `android/`.
4. **Add a short entry to the change history** at the bottom of this file and to `README.md`.
5. **Check performance on a slow phone.** The test phone is an Infinix HOT. Do heavy work once and cache it in sprites. The main view is drawn on the GPU (see "Drawing engine" below): `ctx.filter` (blur) does nothing there, and additive glow (`'lighter'`) is free.
6. **Every building stays on its own lot.** Seen from the camera, a building's picture may rise as high as it likes, but nothing may reach left or right of its lot's side corners or below its lot's two front edges (onto the road or the next lot). Only shore buildings (pier, beach, marina, ferry) reach out over the water on purpose. Ground shapes use the 2:1 shape of the tiles: a circle on the ground of r tiles is an ellipse of 45·r by 22.6·r units, so the biggest circle on a 3×3 lot is 68 by 34. Trees drawn with `kit.tree` on a lot are kept inside it automatically (`FOOT`).
7. **Changing a cached picture after it has been drawn?** Call `touched(canvas)` (or `touched(canvas, x0, y0, x1, y1)` for a part) from `gl2d.js`, or the GPU keeps showing the old one.

## The push command

First delete the old `skyline.zip` from Downloads, so the browser doesn't save the new one as `skyline (1).zip`. Then download the new zip and run:

```bash
cd ~/Downloads/skyline
unzip -o ~/Downloads/skyline.zip -d ~/Downloads/skyline
npm run android:sync && (cd android && ./gradlew assembleDebug) && adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

Then close the game fully on the phone (swipe it away from recent apps) and open it again. It should say **"Updated to version X"**.

### What each part does

- `unzip ... -d ~/Downloads/skyline` puts the new files into the project folder. The `-d` must point at the **skyline folder**, not at Downloads.
- `npm run android:sync` builds the web game and copies it into the Android project.
- `./gradlew assembleDebug` builds the APK. Look for **BUILD SUCCESSFUL**.
- `adb install -r` installs it on the phone over USB. Look for **Success**.

The `&&` means each step only runs if the one before succeeded. If one fails, the rest is skipped and the phone keeps the old version. That's easy to miss in a long build log.

## Troubleshooting

**Check which version is on the phone:** Menu → the line at the bottom says `Skyline 0.9.0 · built (date) UTC`.

**Check the project folder has the new code:**
```bash
cd ~/Downloads/skyline
grep '"version"' package.json
```

**Check the zip is the new one** (it should list `src/game/audio.js`, with no `skyline/` in front):
```bash
unzip -l ~/Downloads/skyline.zip | grep -E "audio.js|package.json"
```

**Is the phone connected?** It should be listed as `device`. If it says `unauthorized`, accept the "Allow USB debugging?" prompt on the phone.
```bash
adb devices
```

**`zsh: no such file or directory: /platform-tools/adb`**: `$ANDROID_HOME` is not set. Use plain `adb` (it lives at `/usr/bin/adb`), which the push command above already does. The SDK copy is at `~/Android/Sdk/platform-tools/adb`. Stick to one of them, since mixing the two causes "adb server version doesn't match" errors.

**`INSTALL_FAILED_UPDATE_INCOMPATIBLE`**: the app on the phone was signed differently. Uninstall it first (this deletes the saved city on the phone), then install again:
```bash
adb uninstall com.wyntek.skyline
adb install android/app/build/outputs/apk/debug/app-debug.apk
```

**Install says Success but nothing changed**: close the app fully and reopen it.

**Game is laggy**: since 0.8.7 Pretty should hold up in busy views; if not, Menu → Graphics → **Smooth**. Leave Lens focus off. To measure it, open the test tools (tap the version line 5 times): the Frames line shows fps, average and worst frame time over the last 2 seconds.

## What was built (version 0.5 series)

### Systems that now actually affect the game
- **Happiness** drives growth. Above 60%, homes grow faster and taxes come in more reliably. Below 35%, residents move away. Happy residents pay more tax (0.8× to 1.2×).
- **Traffic** jams lower land value, add pollution, make commutes longer and lower happiness. Good bus coverage takes cars off the road.
- **Commutes:** homes need jobs within reach by road (18 road tiles, plus up to 12 more with bus coverage), and workplaces need workers nearby. Jammed roads count as longer trips. New Commutes map view.
- **Education:** level 3 offices and industry need schools; level 4 needs a university. **Health:** healthy workers pay more tax.
- **Highway:** enters from the map edge. Nothing grows until your roads connect to it. Industry needs it to sell goods (half tax without it). Older saves get a highway routed to their existing roads automatically.

### Debt instead of game over
- A negative balance is money owed to the regional bank, at 2% interest a month. There is no game over.
- Services close in stages as the debt deepens. Below $0: ordinances paused and amenities closed. Deeper: schools and buses close. Deepest: police, fire and health care close. The stage limit scales with city income (at least $4,000).
- Closed buildings cost only 20% upkeep and show a lock badge. Closed fire stations send no trucks, and closed terminals run no buses.
- Nothing new can be built while in debt, but bulldozing still works, so you can cut costs.
- Bank tab: loans of $10k (12 months), $25k (24 months) and $60k (36 months), up to 3 at a time. Paying early saves 10%.

### Understanding the city
- **Inspector:** with no tool picked, tap any tile to see what the building needs and the exact reason it isn't growing.
- **Advisors** tab with plain-language problems and a "Show on map" button. A **news ticker** shows monthly headlines.
- **Charts:** population, treasury, income vs costs, happiness, plus a happiness breakdown.
- **8-step guide** for new cities.

### Progression
- **Unlocks by population:** 300 (plaza, library, bus terminal), 600 (pumping station, police and fire HQ, recycling, transfer station), 1,000 (hospital, museum), 1,500 (university, waste-to-energy, water treatment), 2,500 (stadium, skyscrapers, recycling complex).
- **Level 4 buildings:** skyscraper (160 residents), office megatower (95 jobs), hi-tech campus (70 jobs, low pollution).
- **New goals:** connect to the highway, Campus town, Reach for the sky, Clean books, Skyline (25,000 residents).

### Graphics and sound
- Natural grass variation, water that deepens away from the shore, textured asphalt with tire wear and curbs, soft shadows, reflective windows with blinds and curtains (and varied lighting at night), shaded trees, a highway sign at the map edge, aerial haze.
- Graphics quality: Auto / Pretty / Smooth, plus optional Lens focus (tilt-shift).
- Fully synthesized sound, with no audio files: city hum, birds by day, crickets at night, rain, effects for every action, and generative music. Menu → Sound.

### Fixes
- Camera can now reach every edge and corner of the 96×96 map (the old limit was left over from the 64×64 map).
- Version line in Menu and an "Updated to version X" message on first launch.
- Hidden test tools in Menu.

## Drawing engine (built in 0.5.9)

The main view is drawn with **WebGL2 on the graphics chip** (`src/game/gl2d.js`). It offers the renderer the same calls as the 2D canvas it was written for (paths, fill, stroke, drawImage, gradients, patterns, one clip, text, save/restore, transforms, `'lighter'`), so `renderer.js`, `construction.js` and `smoke.js` draw exactly as before.
- Every cached picture is packed into up to 5 texture pages of 2048×2048 the first time it's drawn; the least recently used page is wiped and refilled when they're full. Big or changing pictures (ground cache, sea, ripple pattern) get their own texture, with mipmaps for smooth zoom-out.
- A frame goes to the GPU in a handful of draw calls. Additive glow is done in the same batch (zero-alpha trick in the shader).
- If WebGL2 isn't available, it falls back to the old 2D canvas automatically.
- Test tools show "Drawing with: GPU (WebGL2)" or "Canvas 2D", with a button to switch engines (it reloads the game) to compare speed on the phone.
- Pictures drawn *into* cached canvases (sprites, ground cache) still use the normal 2D canvas; that work is done once.

## Harbor ships (built in 0.5.13, Water part 2, first half)

- `src/game/ships.js` (`Ships`, made in `game.initWorldLife`, updated every frame with the sim). Every 3 s `scan()` finds harbors: industry lots by a lake or the sea (`shore >= 2`) with a level. Each gets a berth: the nearest open-water tile within 2 tiles, on water of 16+ tiles or reaching the edge.
- **Open water** is water without a bridge on it (`nav`), split into connected parts; a part touching the map edge is the sea. Ships never pass bridges.
- **Sea harbors** get `cargo` ships (1/1/2/3 by level): they spawn off the nearer third of the sea's edge, sail to the berth, lie along the quay 25–50 s, sail back to the edge and fade. **Inland harbors** (and sea harbors cut off by a bridge) get `barge`s (1/1/1/2) that shuttle to the other harbors on that water in turn, or to the farthest open water when there is only one. At most 14 ships on the map.
- **Routes** are distance fields (Dijkstra over open water, tiles next to land cost 2.5×, no corner cutting), cached per destination and cleared when a bridge changes (`bridgeSig`). At most one new field per frame (about 1 ms on a PC); ships waiting for one sit still a frame. Ships steer two tiles ahead and never move onto land (`wet`); if they bump a corner they go back to the middle of the tile first.
- **Drawing:** `renderer.ship()`, drawn live (few ships, simple shapes) in painter order with the buildings, so harbor buildings correctly hide ships tied up behind them. Hull colours etc. are `HULL`, `BOX`, `CARGO` at the top of `renderer.js`.
- **Rules (sim.js):** `analyzeSea()` (run with the road analysis) sets `seaLink` per land tile: 1 = within 2 tiles of open sea, 2 = only reaches the sea past a bridge. `linkedOut(i)` replaces the plain highway check for growth and decay: industry with `seaLink 1` ships its goods by sea. `ports` / `portsBlocked` counted in `recount()`. With a port, industry never pays half tax and gets +0.08 demand (Freddie: this demand bonus was not in the plan; drop it if unwanted). Inspector row "Ships to the sea"; Advisors warn about blocked harbors.

## Traffic and speed (built in 0.6.1)

- **Trips, not wandering cars** (`flow.js`, `sim.flowM`): districts of 6×6 tiles send workers to jobs (attraction × e^(−time/28)), residents to shops (35%, e^(−time/14)) and industry's lorries to the highway, minus the share that takes buses or the metro. One quickest-route search per district, trips pushed back along the route tree in one sweep. `PEAK` = 0.08 turns daily trips into the busiest hour. Capacity per tile: street 55, avenue 120, highway 170. Travel time `base × (1 + 0.5 × load⁴)` (base: avenue 0.7, highway 0.6), capped at 5×, so later passes route around jams. Passes run 2.5 ms per frame (1.5 on Smooth), every 6 game days or when roads change, blended 50/50 with the last result; the first three passes run back to back.
- **Uses:** `sim.analyzeRoads` takes jams (load above 0.85) and commute times from it and reruns when a new pass finishes; Views → Traffic shows load; the road Inspector shows trips against capacity. The old per-frame car-count map is gone.
- **Cars follow it:** `Traffic` spawns cars on road tiles in proportion to trips (`flow.pick`), turns them toward busier roads, and replaces each after 10–24 tiles. Citizen drivers take the quickest route by travel time (`agents.bfs`, now a Dijkstra over `flow.cost`; route cache cleared when the traffic picture changes).
- **Speed:** vehicles queue by checking only their own and the next tile (`followPass`, no longer every vehicle against every other); the renderer sorts vehicles into tiles with reusable arrays instead of a new map every frame; off-screen rows of the map are skipped before any tile work; status badges and traffic lights are cached pictures (lamp glow added live); building shadows are only redrawn when the view, the sun or the city changed; the sprite warm-up gets 1.5 ms instead of 3. In a test city of 47,000 residents the drawing work per frame went from 46 ms to 27 ms on a PC.

## Still view layer (built in 0.8.3)

- **Why:** drawing every tile, tree and building each frame was most of the work, and most frames show exactly the same city. Freddie wants every graphics setting kept and the phone cool.
- **How** (`renderer.draw`): when the camera hasn't moved for 6 frames (`stillF`), and the far-zoom city picture isn't in use, `viewSig()` makes a signature of the view (camera, light, season, quality, traffic version, tracks, zebras, wetness, ground cache, and every tile in view: lot, building, look, tree, power, water, garbage, lit windows, site, rubble). When it changes, the ground pass and the object pass are drawn once into a screen-sized texture (`gl2d.layerBegin` / `layerEnd`, a framebuffer with stencil) with `L` set: trees don't sway, and moving or animated things are noted in `layerLive` instead of drawn (building sites, traffic lights, flags and wind turbine blades); badges, smoke and neon positions are kept in `layerLists`. Every frame: water, reflections, waves and boats, then `drawLayer()` (one quad, the texture is upside down so v runs 1 to 0), then `liveLayer()`.
- **Live pass** (`liveLayer`): tiles with live things (noted ones, cars and people, ships, fires) in painter order; after a tile's things are drawn, `occluders()` redraws the still pictures of later tiles whose pictures reach into their box (up to 26 diagonals ahead), so a car behind a tower stays hidden. What stands on each tile is looked up once per layer (`stC`, `staticPic`) so the check is just numbers.
- **Clipped redraw (0.8.4):** `occluders()` runs inside a scissor box (the moving thing's box plus 1 px), so the later tiles it redraws only touch pixels where the car was drawn. Without it, a redrawn picture covers buildings further forward that don't reach into the box. Car boxes are 24 (buses and trucks 34) units wide each side, 50 at dusk and night for the beams.
- **When pictures are missing** (sprite budget), `layerMiss` makes the layer redraw every 12 frames until it is complete. Moving the map uses the normal drawing (with tree sway). Not used with the 2D canvas fallback. `renderer.noLayer = true` turns it off for comparison.
- **Measured:** dense test city, same view: draw work about 34 ms → 6 ms per frame (desktop browser); the pictures match except for the badges' bob. `reflections()` now keeps the list of waterfront lots (refreshed every 3 s) instead of scanning the whole map each frame.

## Dirt tracks (built in 0.7.4)

- **Where:** `sim.tracks()` runs at the end of `anNetworks` (every analysis). Built zoned lots without a road on one of their four sides (`sim.fronts(i)`) get a track. Tracks run along tile sides between corners: one breadth-first search from every corner that touches a road (bridges don't count) gives each corner its distance to the road, up to 6 sides; a side can be used when both tiles beside it are open land, lots or parks (not water, roads or service buildings). Each lot walks downhill from its nearest corner (front corners first), preferring sides already laid, so a back row shares one lane. `trackX[c]` / `trackY[c]` mark the sides from corner c = (cx, cy) along x or y (corner grid (N+1)²); `trackLot[i]` the lots served; `trackVer` changes when the layout does. A lot touching a road only diagonally counts as track-reached with no lane drawn.
- **Growth:** `TRACK_MAX` = 2. In `blocker()`: a lot at level 2 or more without frontage can't grow ("Only a dirt track reaches it…"). Nothing shrinks because of it, so taller buildings from before 0.7.4 keep their height. The old rule stays: a lot needs a road within 2 tiles at all. Commute +2 for track lots (`analyzeRoads`). Inspector row Access. Advisor (Planning, tip) when 4+ held-back lots have demand, with `tile` = the lot with the most held-back neighbours; advice with a `tile` but no `view` now also gets Show on map.
- **Drawing:** in the object pass, after a tile's building, `renderer.trackSprite(axis, mode, wet)` draws the lane inside that tile along its front-left (`trackX` at the corner below it) or front-right side (`trackY` at the corner to its right), 0.22 of a tile wide, so buildings in front cover it and the one behind doesn't. Cached per side, lighting, season and wet (rain above 0.3). Skipped below zoom 0.45.

## Roads, power and sewage (built in 0.9.0)

The agreed 0.9.0. It makes the game harder on purpose. A game day passes in about a second at 1x while the clock's day lasts 180 s, so anything tied to the clock's hour (daylight) can't drive the economy: it would mean months of darkness. Solar is therefore worked out as an average over day and night, and the hour only shows in the Inspector.

- **Road wear** (`roads.js`): `w.wear` (0..100, saved with the world) grows each game day by `0.035 + 0.38 × load^1.3` (avenues × 0.7, bridges × 0.6; the highway doesn't wear). A street at capacity needs a repair after about six months, a quiet one after two to three years. Cracks from 60, potholes from 85 (`renderer.crackSprite`). Travel time `× (1 + (wear − 60) / 70)` in `flow.baseOf` (`wearMul`).
- **Repairs**: crews `max(1, round((1 + road tiles / 90) × Road repairs budget))` (new fund group `roads`, City → Services, 50 to 150%). Each free crew takes the worst road at 72 or more: below 92 one lane closes for 5 days ($25; capacity halved, travel × 1.6), at 92 or more the road closes for 9 days ($90; travel × 30 so routes go round, `capMul` 0.05; `Mover.openDirs` and `services.path` don't drive into it). `w.fix` (1 lane, 2 closed, saved), `sim.repairs` (tile → big, days left; saved). Costs go into the month's costs (`lastRoadSpend`, Budget: "Road repairs last month · worn roads"). Drawn by `renderer.roadWork` (cones and a patch with a worker; red and white barriers, a dug-up hole, a digger and a worker). Inspector: Condition, and Repair now (`30 + wear × 1.5` dollars, instant, `sim.repairRoad`, action `rd:now`). Advisor when more than 8% of road tiles are worn (Show on map: the worst).
- **Power** (`sim.plantOutput`, `plantInfo`, Inspector "Power output" and "Why"): solar (`peak` 320) makes 160 on average; wind (`peak` 20) makes `20 × sim.windK` (set by `game.update` from a slow wave and the weather; turbine blades turn with it, `renderer.bladePh`); nuclear needs cooling water: a lake or the sea within 2 tiles, or a pipe touching it that can give 300 water (a consumer, `cool`), else 25%; gas needs a road linked to the highway (the gas main) or makes nothing, and cooling (100 water) or 60%; coal needs a road linked to the highway for its lorries or makes nothing. Cooling through pipes is checked against the previous analysis (`coolOk`) and a change asks for a new one. **Battery storage** (id 33, 1×1, $2,500, touching a line, unlocks at 1,200): adds up to 80 on its network, out of what solar and wind there can't deliver right now (`vari`). Advisor when a plant makes less than half (not for sun and wind).
- **Coal lorries** (`services.coalRun`): up to two per coal plant, from the highway at the map edge and back.
- **Sewage** (in `anNetworks`, after the water demand): buildings level 2 and up on a pipe network that has water send 90% of their water use as sewage. A **Sewage works** (id 34, 2×2, $4,500, touching a pipe, needs power, 30% without, unlocks at 400) cleans up to 700 on its network; 35% of what is cleaned comes back as water for that network. The rest comes out at the water tile nearest the network's middle (within 40 tiles), or in a ditch on dry land (`sim.sewage`: total, treated, outfalls, buildings). In `anLand` it pollutes around the outfall and spreads through connected water (`sim.dirtyWater`, `dirtyList`; up to 18 tiles for big amounts), fouling the shore next to it. Beaches, piers and marinas lose up to 75% of their pull with dirty water in front (`shoreClean`, Inspector "Water: dirty with sewage"). Drawn as a brown-green tint over the water. Budget: "Sewage treated". Advisor with Show on map at the outfall.
- **For existing cities**: inland nuclear plants without a pipe drop to 25%, coal and gas plants without a road to the highway stop, and solar farms average 160 instead of 200. The advisors and the plants' Inspector say why.

## Busy views on Pretty (fixed in 0.8.7)

Freddie: the game lagged when a lot was happening, on Pretty (which stays: it's how he wants it). Measured in a dense test city at night (about 140,000 residents, a few hundred cars and people in view):
- **Texture pages thrashed.** The pictures in a busy view needed about 19 million pixels; the 5 pages of 2048×2048 hold about 21 million, less what packing wastes. Pages were wiped and refilled about 8 times a frame and about 63 MB of pictures went to the graphics chip each frame (in the test browser the GPU engine eventually crashed). Smooth didn't suffer because its half-size pictures fit.
- **Most of that was empty space.** Building pictures are drawn on generous canvases (a tower: 320×580 for a 128×376 building). `make()` in `sprites.js` now notes where every shape lands while the picture is drawn (`watch()` wraps the canvas calls: paths, arcs, ellipses, rects, text, images, and follows translate/rotate/scale/save/restore; shapes inside a clip don't count, the clip's own path does) and `trim()` keeps only that box plus `EDGE` (3 units), on a 4-pixel grid so `mip` copies line up as before. `ox`/`oy` move with it, so nothing shifts. A busy view now needs about 5 million pixels; no page refills, about 0.1 MB uploaded per frame, and the GPU blends far fewer transparent pixels. Reading the pixels back to find the edges was tried first and made each new picture about 4× slower, so don't go back to that.
- **Page eviction** (`alloc` in `gl2d.js`): when all pages were drawn from this frame, the one with the fewest pictures drawn from it this frame (`page.hits`) is wiped, instead of whichever comes first.
- **One batch for the live pass:** `liveLayer` redraws what stands in front of each moving thing inside its box. That box was a GPU scissor, which ended the batch twice per tile (75 to 200 draw calls a frame with lots of traffic). Now `ctx.clipBox(x0, y0, x1, y1)` / `noClipBox()` cut the pictures and their texture coordinates on the CPU (pictures only, no rotation), so it stays in one batch: about 6 draw calls a frame. Checked pixel for pixel against the scissor version.
- **Things showing through buildings with the still view (bug since 0.8.3):** `staticObj` remembered a tile as "nothing here" when its picture wasn't made yet in that frame (sprite budget), until the next layer rebuild, so cars, people and building sites behind it were drawn over it. Such entries now carry `again` and are looked up again next time. Building sites also grow their redraw box by `siteBox()` (`construction.js`), since a crane reaches past the trimmed picture.
- **Tall buildings at the bottom edge (bug):** the object pass skipped tiles more than 60 units below the screen, so a tower standing just below the edge, reaching up into view, was missing (and with the still view showed up only in patches around passing cars). Diagonals down to `H + 360 z` are now visited; tiles past the old edge draw only their still picture (`lowTall()`). `viewSig` covers the same band. `staticPic` now also keeps empty (abandoned) buildings dark, like the object pass.
- **Measured after all of it** (same test city, still camera): drawing work about 27 → 12 ms a frame on a PC, draw calls 87 → 8, texture uploads 117 MB → 0 a frame. The still layer and the fully drawn frame now differ only where the still view holds things still on purpose (about 4,000 of 475,000 pixels).
- **Still layer in a busy city:** a change in the city (growth, badges, a traffic pass) redraws the layer at most every 15 frames and 0.4 s; the camera, light, season, quality, overlay or your own building and bulldozing (`g.history`) still redraw it at once (`layerVK`). A building site that finishes in between is drawn live until the layer catches up, so nothing blinks.

## People, goods and the region (built in 0.8.6)

All sim work is in `sim.js` (tested headless in Node: `new Sim(new World(seed, map))`, then `tick()` and `stepAnalyze()` in a loop).
- **Empty buildings** (`sim.aband`, per tile: 0 lived in, else the reason, `ABANDON_WHY`): in `tick()` a built lot with a problem (no power, cut off, no jobs or workers in reach, homes below 35% happiness, demand below -0.25) first goes empty (people leave, `moveOut`), then if it lasts is torn down a level at a time, still empty. When the problem is gone, people move back in (`moveIn`). Empty buildings hold no people or jobs (`recount`), can't grow (`blocker`), count in `bld.empty`, and cost up to 4 happiness. Renderer: windows dark, no smoke or neon, a grey boarded-up badge (`'empty'` in `badgeShape`), part of `viewSig`; the far city picture (`citycache.js`) keeps them dark. Saved in `state().aband` as `[tile, reason]` pairs.
- **Families** (`sim.family(i)`): a surname from the tile hash, wealth, the nearest workplace and a wish (the weakest coverage or worst nuisance at the home, `WISH`). Shown as Neighbours / Work / Their wish rows in the Inspector.
- **Wealth** (`wealthOf(landValue)`: below 50 working class, below 68 middle class, else well-off): residential tax is paid on `taxBase` (residents × 0.8 / 1 / 1.4) instead of plain population.
- **Goods** (`sim.goods`, in `recount`): industry makes `GOODS_PER_JOB` per job (tech 0.3), shops need 1.3 per job. Local supply nudges shop demand (+0.02 to -0.03); a shortage raises industry demand (up to +0.12). Shop tax × (1 - import share × 0.2, or × 0.5 without the highway or a port); industry tax × up to 1.1 for goods sold locally. Inspector rows on shops and industry.
- **Factories ignore their own smoke**: `landValue(i, IND)` adds back up to 16 (pollution × 0.28). Before this, industry almost never reached level 2.
- **Jobs**: `sim.workforce` = residents × 0.6 (scaled by the adult share). `demandWhy()` gives a plain reason per zone. Top bar: jobs chip (unemployment %); the R C I bars are a button that opens City → People.
- **Ages** (`sim.ages`, monthly in `monthlyPeople`): kids grow up, adults age, seniors pass on (later with health coverage); newcomers are mostly young. Schools count more in happiness with more kids, health care with more seniors.
- **Approval and elections**: `approval` moves 30% a month toward 0.75 × happiness + up to 15 for jobs + up to 10 for the books. Every January from the second year: 50% or more wins a grant of $500 + $0.80 per resident and +3 happiness for 6 months; less caps taxes at 9% for a year (`taxCap`, enforced in `game.setTax` and the slider max) and −2 happiness for 4 months. Event `vote` plays a sound and a toast.
- **Service budgets** (`sim.fund`, 50 to 150% per `FUND_GROUPS`, a building's group from `fundGroup(def)`): upkeep × budget, coverage strength × (0.5 + 0.5 × budget), radius × (0.85 + 0.15 × budget); parks' upkeep follows the Parks & fun budget. City → Services.
- **Trade with neighbouring towns** (`sim.trade`, needs the highway): sell spare power ($0.25 a unit a month) and water ($0.04), and send garbage that no landfill can take to the region ($3 a building a month; those buildings count as collected in `anNetworks`). City → Services; Budget shows the totals.
- **UI** (`App.jsx`): City panel has 8 tabs (`.seg.tabs8`), new People and Services tabs.

## Water, part 2 (built in 0.5.13 and 0.5.15; the original plan)

The rest of the water plan, carried over from 0.5.6. Keep the three water styles in mind: big ships only on lake and sea harbors.

### Harbor ships (built in 0.5.13, see above)
Each harbor (lake or sea industry lot) has ships coming and going, more as it grows. Use the boats in `boats.js` as the base.
- Water that reaches the **map edge** counts as open sea: ships sail in from the edge, dock at the harbor for a while and sail back out.
- On an **inland lake**, barges and small cargo boats shuttle between the harbors on that lake, or between a harbor and a marina if there is only one harbor.
- **Gameplay:** a harbor on water that reaches the map edge also counts as a way to ship goods out, like the highway (industry pays half tax without one). Ships can't pass a bridge across a harbor's only route to the sea; say so in the Inspector instead of making it a hidden rule.

### Things to build on the water
Each unlocks at a population level, like other buildings, and sits on the shoreline, partly over the water.
- **Pier:** cheap, early. People stroll and fish. Small land value boost nearby.
- **Beach:** placed on sand. Umbrellas and swimmers by day. Counts as an amenity, like a park.
- **Marina:** moored boats that sail out on its lake. Bigger land value and amenity boost.
- **Ferry pier:** works like a bus terminal across water. Two ferry piers on the same lake get a ferry between them, which stretches commute reach the way bus coverage does.

### Notes for whoever builds it
- Keep all new art cached as sprites (see `sprites.js`, `mip()` for zoomed-out copies). Nothing drawn live per tile per frame.
- New buildings on water must work with the ground cache in `renderer.js` (`updateGround`, redraws changed tiles and their neighbors) and with `shoreMask` / `waterRegions`.
- Boats already hide under bridges (`renderer.boats`); harbor ships should do the same.
